# S4.1 路由可靠性与分类服务

基线 main `6505471`，目标 DSH `0.2.1-alpha.2` / Node.js ≥22。
本轮保留 chooseRoute、deriveLadder、上下文信封和分类低置信度的原有保守决策策略；不增加分类器、模型评分或运行时依赖。

## 问题与修复

| 问题 | 实际改动 |
| --- | --- |
| 填了 URL 就难以分辨是否可用 | 模式感知静态检查与真实分类验证分离；未知目录/凭据/当前模型不标 Ready |
| 分类失败直接放行也叫 Fallback | 默认放行为 Bypass；只有授权备用模型到达原生 Header 后才确认 fallbackApplied |
| 输入框标签过长 | 紧凑中文控制状态 + 模型名，完整档位、原因、建议、分类来源和计划放在原生 Menu |
| 配置页长且缺少指导 | 顶部模式说明，非选模模式折叠候选，单项能力配置折叠，目录中已启用模型优先展示 |
| NeoHorse 不方便设置 | 明确应用到草稿的托管/本地预设；保存仍由原生 ConfigForms 修订校验和持久化完成 |
| 缺少最小诊断 | 每会话最近 20 Turn 的结构化内存记录；工具步骤更新同一条，不另建持久化系统 |

## 就绪规则

优先级：Disabled → Conflict → Manual/手动锁 → 当前模式必要配置 → 目录/当前模型 → 执行降级 → Unverified/Ready。

| 模式 | 需要检查 |
| --- | --- |
| FULL_AUTO | 有效 System One URL、可解析凭据、启用且可解析的候选；模型锁定时转为检查原生固定模型；档位锁定时检查固定约束 |
| EFFORT_AUTO | 不要求候选；检查原生当前模型及合法档位、分类配置。未声明档位显示 Native/模型默认，不判为模型不可用 |
| MODEL_AUTO | 授权候选、目录和固定档位兼容；空 fixedEffort 需要当前原生档位事实。模型被锁定则保留手动控制 |
| MANUAL | 不需要 Jev、凭据或候选，显示由 DSH 原生选择控制 |

仅配置满足是 Unverified；Ready 表示**相同配置最近一次真实 System One 分类成功**且相关目录/当前模型已知，不保证持续网络健康、分类准确率或最终 LLM 成功。显示验证时间/耗时，无后台网络轮询。
配置或凭据变更、Host 重启会使验证失效；分类等待期间变更凭据也不能由旧响应恢复验证。新端点草稿不继承旧端点失败。
设置页没有绑定某个当前 Session，EFFORT_AUTO 因而可能提示当前模型未知；聊天菜单用该 Session 的已提交 Header 核对，避免猜测全局“当前模型”。

## 控制状态与原因

- Auto：自动配置被选择；实际模型/档位仍独立取原生 Header。
- Native：正常保留原生控制，或最终 Header 覆盖了提议。
- Manual：手动模式、锁定或原生显式选择。
- Bypass：自动决定未应用，原请求被保留；这可能仍是之前自动写入的模型，不承诺恢复最初强模型。
- Fallback：当前模型明确不可用时，沿用现有策略应用配置且授权的备用模型；以 Header 确认。未执行提议不算切换。
- Blocked：现有上下文容量保护主动阻断；不会吞掉 ContextCapacityError。
- Conflict：让出与 Jev Effort Selector 冲突的自动控制。

`explainReason` 覆盖 no-url/no-key/timeout/failed/invalid-choice/no-compatible-model/validation-failed/context-too-large/context-capacity-blocked/router-error/manual/native-manual/conflict/settings-changed，以及明确 HTTP 拒绝与原生覆盖。只返回建议和安全原因码，不返回响应原文/堆栈。
标签只显示最近 Header，Menu 区分计划与实际，不把选择成功解释为远端调用成功。

## System One 协议与预设

实际配置仍仅为 apiUrl/apiKeyEnv/classifierModel；**没有新增配置存储或配置字段**。

| 预设 | URL / 模型 / 默认凭据引用 |
| --- | --- |
| Jev System One | 保留现有 URL / jev-latest / 不改当前引用 |
| NeoHorse-Jev · TokenRhythm | https://tokenrhythm.studio/v1/systemone / NeoHorse-Jev-4B / TOKENRHYTHM_API_KEY |
| NeoHorse-Jev · 本地部署 | http://127.0.0.1:8080/v1/systemone / NeoHorse-Jev-4B / TOKENRHYTHM_API_KEY |
| 自定义 | 保留手工编辑的完整 URL、模型 ID、凭据引用 |

选择下拉项本身不改配置；点击“应用预设到草稿”才设置字段，保存前可撤销。自定义凭据引用和 confidenceThreshold 不改；只有空值/已知默认引用使用 NeoHorse 默认引用。不会暗中保存各引擎的另一套配置；返回旧服务时明确提示核对旧 URL/模型，不自动清空地址。
localhost 指 Host 所在机器/容器/WSL；插件不启动本地模型。当前保留非空凭据要求，匿名本地服务不提供特殊旁路。托管服务受平台密钥、灰度权限和额度限制。

唯一请求仍是 askJev 的 POST System One，保留 tier/role 与有历史时的 relation，绝不使用 Chat Completions。
- 验证合法 Choice，拒绝异常 confidence；NeoHorse 必须有对应完整类别概率、有限的 [0,1] 值，归一化容差 0.02。Jev 仍允许省略 probabilities，以保持原服务兼容。
- 托管协议允许 confidence 省略：策略内部按未知/0 走原来的保守 top-two 与 continues 策略，诊断展示未知；不改变 Jev 默认阈值 0.6。
- NeoHorse confidence 是本地分布统计量，**不等于正确率**，不可与原版 Jev 直接比较。同数值阈值仅保留用户策略，不代表跨引擎校准。
- 限制请求 JSON 1 MiB、响应 64 KiB、既有超时/取消；拒绝 HTTP 重定向，不转发凭据。413/422/401/403/429/529 分开解释，其他 HTTP/传输错误安全降级，无自动重试。
- 上游默认 state 2048 tokens、每题 8192、总分支 32768；不引入 tokenizer，不静默截断，超出由服务 422 拒绝并 Bypass。

## 连接检查的安全边界（保守替代）

**浏览器“测试连接（静态检查）”不发出网络探针，不验证 HTTP 可达、模型授权或协议可用。**
Host 的无参数 getSetupState 仅查看已保存配置、URL 格式、凭据可解析布尔值、已发生的真实分类结果；浏览器不能传 URL、密钥或聊天内容。草稿保存前禁止检查。

目标版本 Typert `PeerScope` 明确不包含“谁/允许做什么”，没有确认可复用的插件级探针授权契约；Host 的 settings.writable 不能当作调用者权限。本轮采用任务 D3 明确允许的静态检查替代，不创建带凭据 SSRF/通用 HTTP Remote，也不把 /health 当成协议证明。
Host-only `probeJev` 用固定合成输入复用 askJev，返回引擎、模型、耗时、时间和安全结果；**不在 Remote descriptor 中导出**。本地 HTTP 测试验证了探针，但 Web 不可调用。后续只有明确公开授权契约后才考虑开放网络按钮。

## 记录与隐私

每会话最多 20 条内存记录，每 Turn 一条；包含时间、模式、Local/Jev/NeoHorse、tier/role/confidence（可未知）、耗时、计划、最后提交的真实模型/档位、状态、原因、是否确认备用切换。工具步骤与安全阻断更新当前条目。
记录实际值来自公开 session/event 的 request/header，配置不变未重复 Header 时读原生 adaptiveRouter 投影。Header 覆盖提议时保留计划但状态归 Native；Blocked 不被旧 Header 降级。
不保存聊天/系统提示/工具正文、密钥、Authorization、请求体、响应原文或堆栈。不写磁盘；Agent/Session dispose 和插件卸载清理，晚到响应不能重新填充记录。
只保留既有最新诊断读取；**不新增可任意枚举 Session 历史的 Remote**。20 条历史只在可信 Host 服务内，Menu 使用最近一条。该版本共享 Host 的认证边界不等同于多租户逐用户 ACL，不承诺该能力。
