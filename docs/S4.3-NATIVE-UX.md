## 配置与连接真实性

模式、候选与服务继续通过 `configForms.get('adaptive-router').mutate(ops, revision)` 保存。单击预设只改草稿；SettingsForm 离开时丢弃，显式撤销同时清理基线。保存失败保留草稿；只读禁写，连续保存仍同步互斥。

「API Key 凭据」输入的是名称，例如 `TOKENRHYTHM_API_KEY`，不是实际密钥。没有 Credential 写入/查询密钥值的新接口。

「检查配置」只检查已保存配置；有效地址和可解析凭据显示“配置正常，等待首次实际调用”，不会发分类探针。真实分类成功的 Host 证据才显示服务已验证；重置连接、配置修订或连接草稿变化会废弃晚到的旧检查提示。

核对 [TokenRhythm 官方接口文档](https://tokenrhythm.studio/docs/api-integration)（2026-10-17）：`/v1/decision` 为推荐接口，`/v1/systemone` 是同请求体的兼容格式，响应可另含 usage/extensions。插件继续使用已验证的 System One Choice，不改变路径、协议、confidence 或分类算法。

## Router Lab 错误调查与边界

原 Host 把权限、存储和修订等异常合并为 `lab/rejected`，客户端把所有失败解释为本地 operator 限制；因此原提示无法确定真实原因，并不能说明合法本机访问必然被误拒绝。本轮真实本机 Profile 读取成功，没有证据需要修改授权条件。

| 原因 | 安全提示/处理 |
| --- | --- |
| Host 开放远程 authority、非明确 loopback 或未知环境 | 当前环境无法查看实验数据；说明使用本机 Profile |
| Peer 不符或反馈/清空时配置只读 | 当前账户无权执行此操作 |
| 公开存储不可用 | 数据存储暂不可用；聊天不受影响，不显示零指标冒充可用数据 |
| 反馈记录 revision 过时/记录已清空 | 记录已更新；刷新后重试 |
| RPC 抛错/连接中断 | 连接已断开，请重试 |
| 其他/未知错误码 | 加载失败，请重试；不展示任意服务端文本 |

技术详情只展示白名单代码。目标版本公开浏览器 RPC 把原生 admission 的 401/403 抛为固定格式 HTTP 错误；客户端只提取该格式中的状态并显示权限提示，不将其误判为断网，不展示错误原文。Host 仍执行原生 admission、同一 operator 实例、明确 loopback、禁止 remote authorities、写操作 settings.writable；未新增 endpoint、Session 查询或远程数据权限。请求初始化使用已有 ready Promise；等待时显示加载状态，无存储时明确不可用，不创建兼容存储。实验 Schema、Usage、请求归属、采集与数据安全逻辑完全未修改。

打开实验面板时只读取当前本地统计，不开启采集、不发外网请求。关闭采集保留数据；导出仍用户触发，清空仍确认，更新仍用户点击。连接 reset 清除快照、菜单与在途结果；卸载沿用既有 Slot/effect 清理，局部 style 随组件卸载。
